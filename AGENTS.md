# AGENTS.md
## 📜 Project Overview
Telegram **chat-analysis bot** on Cloudflare Workers. Receives messages via webhook, stores them 7 days in Cloudflare KV, tracks per-user activity, and runs several AI pipelines over the chat.

Capabilities:
- **Activity stats** – per-user counters and daily aggregates (`ENABLE_ACTIVITY_TRACKING=true`).
- **Yellow-press summaries** – optimized parallel/hierarchical summary pipeline (`ENABLE_SUMMARY=false` in prod).
- **Profanity detection** – local detector plus criminal-prefilter feed (`ENABLE_PROFANITY_ANALYSIS=false` in prod).
- **Criminal УК РФ analysis** – Qwen prefilter → Durable Object queue → gpt-5-nano final judge with Vectorize legal RAG → violations in D1 → Telegram notifications (`ENABLE_CRIMINAL_ANALYSIS=true`).
- **Admin web panel** at `/admin` (D1 stats, criminal details, chat management).
- **LLM budget tracking** with monthly soft token limits (ADR-001).

Storage: KV for 7-day history, D1 (`summaries`) for aggregates and criminal violations, 3 Durable Objects for counters, day blocks, and the criminal analyzer. Targets ≤ $6 / month.

## 🛠 Environment Variables (set via `wrangler secret put`)
Secrets:
- `TOKEN` – Telegram bot token; **never print** to logs. (required)
- `SECRET` – webhook HMAC header for security validation. (required)
- `OPENAI_API_KEY`, `OPENAI_PREMIUM_API_KEY`, `OPENROUTER_API_KEY` – provider API keys (optional).
- `ALIBABA_API_KEY` – Qwen criminal-prefilter key at the Aliyun MaaS endpoint (optional).
- `LEGAL_RAG_INGEST_KEY` – auth for legal-RAG ingestion (optional).
- `ADMIN_BASIC_PASSWORD` – basic-auth password for `/admin` (optional; user via `ADMIN_BASIC_USER`).

Key `wrangler.jsonc` var groups (source of truth – do not duplicate every var here):
- **Provider selection**: `SUMMARY_PROVIDER`, `PROFANITY_PROVIDER`, `CRIMINAL_PROVIDER` (values `cloudflare` | `openai` | `openai-premium` | `openrouter` | `legal-rag` | `mock`).
- **Feature toggles**: `ENABLE_CRIMINAL_ANALYSIS`, `ENABLE_ACTIVITY_TRACKING`, `ENABLE_PROFANITY_ANALYSIS`, `ENABLE_SUMMARY`, `ENABLE_PROFANITY_FROM_CRIMINAL_PREFILTER`, `SUMMARY_OPT_ENABLED`.
- **Criminal / legal-RAG tuning**: Qwen prefilter (`CRIMINAL_PREFILTER_*`, `QWEN_PREFILTER_*`), final judge (`CRIMINAL_FINAL_JUDGE_*`), legal-RAG (`LEGAL_RAG_*`), queue (`CRIMINAL_QUEUE_*`).
- **Budget limits** (ADR-001): `NANO_TOKENS_SOFT_LIMIT` (20M), `MINI_TOKENS_SOFT_LIMIT` (3M).

## 🏗 Architecture / Data Flow
1. Telegram webhook → `fetch` entry → `handleUpdate` → `recordMessage`.
2. `recordMessage` appends to a `DayBlockManager` DO day block; on failure it falls back to individual KV keys `msg:{chat}:{ts}:{id}` (ttl 7 days).
3. Activity is tracked in `CountersDO`.
4. Async branches: criminal УК РФ analysis (Qwen prefilter → `CriminalCodeAnalyzerDO` queue → final judge with legal-RAG references) and profanity; they ack results back to `CountersDO`.
5. Cron `59 23 * * *` → daily aggregates / backfill.
6. `/admin` panel reads stats and criminal details from D1.

## 🎯 Code Quality & Best Practices

### Clean Code Principles
- **DRY** - Don't Repeat Yourself; extract common logic into reusable functions
- **KISS** - Keep It Simple Stupid; prefer simple, readable solutions
- **YAGNI** - You Aren't Gonna Need It; don't add complexity for hypothetical future needs
- **SLAP** - Single Level of Abstraction Principle; one function - one level of abstraction

### Function Design
- **Single Responsibility**: each function should do one thing well
- **Small functions**: prefer 20-30 lines max, extract complex logic
- **Descriptive names**: function names should explain what they do (e.g., `incrementUserCounter` not `handleCounter`)
- **Early returns**: use guard clauses to reduce nesting
- **Pure functions**: prefer functions without side effects when possible

### Error Handling
- **Fail fast**: validate inputs early and throw meaningful errors
- **Graceful degradation**: handle edge cases without crashing the system
- **Consistent error format**: use structured error objects with context
- **Never swallow errors**: always log or propagate errors appropriately

### Code Structure
- **Type safety**: use proper TypeScript types, avoid `any`
- **Constants**: extract magic numbers/strings into named constants
- **Configuration**: move hardcoded values to environment variables or config files
- **Separation of concerns**: separate business logic from I/O operations
- **Modular design**: group related functionality into cohesive modules

### Testing
- **Testable code**: write functions that are easy to test in isolation
- **Edge cases**: always test boundary conditions and error paths
- **Mock external dependencies**: use mocks for external services (KV, DB, API)
- **Descriptive test names**: explain what scenario is being tested

### Documentation
- **JSDoc for public APIs**: document function purpose, parameters, and return values
- **Complex logic**: add comments explaining WHY, not WHAT
- **README updates**: document any new features or breaking changes
- **Code examples**: provide usage examples for complex functions

## 🔐 Security & Privacy Rules
- Do **not** log full Telegram payloads.  
- Strip PII before saving metrics.  
- KV keys use pattern `msg:{chat}:{ts}:{id}` with **ttl=604800**.  
- History is ephemeral (7 days in KV); D1 stores per-user/daily aggregates and criminal violations.
- Criminal analysis **never stores message text previews in D1 by default** (`CRIMINAL_STORE_TEXT_PREVIEW=false`).
- Logs must stay privacy-safe: no message/payload content, use hashed IDs where needed.
- Workers AI must be invoked with model in `env.AI`. Inputs stay private; Cloudflare **does not train** on them.
- Always validate webhook signatures using HMAC-SHA256.
- Sanitize all user inputs before processing.

# Design

## Context

Дневные агрегаты D1 уже содержат число сообщений каждого автора и длительность голосовых. Почасовой счётчик привязан к конкретной дате UTC. Пересчёт по местной полуночи потребовал бы более детальных исходных данных. Поэтому даты и пиковый час в выпуске явно помечены UTC.

## Decisions

1. **Калибровка до разработки.** На доступной для анализа выборке полных недель посчитать долю групп с каждой наградой, долю групп с любым бейджем и число недель до первого открытия. Разбить по числу писавших участников и показать размер каждой выборки. Для «Часа пик» отдельно показать число недель с доступными четырьмя неделями сравнения. Сохранять только сводные числа. Если выборка мала, оставить пороги предварительными до добровольного пилота. Изменение правил по результатам калибровки сначала вносится в спецификацию.
2. **Одна строка на автора в день.** Из `stats_daily_user` суммируем сообщения, число и секунды голосовых. Для выпуска считаем разных авторов с положительным числом сообщений за всю неделю, для «Без выходных» — отдельно по каждому дню. Из `stats_daily_hour` получаем максимум отдельного часа с датой и 24 значения для графика. Проверяем готовность диапазона по существующей логике покрытия D1 и подтверждения CountersDO. Только доказанно пустой интервал можно представить нулём. Недостающая история сравнения исключает только «Час пик».
3. **Планирование.** Ежедневный cron запускается в 23:59 UTC. На первом таком запуске после закрытия воскресенья смотрим предыдущую завершённую неделю. Обрабатываем включённые группы ограниченными порциями, переносим неподтверждённые результаты на следующий проход в течение текущей недели. После этого пропускаем просроченный выпуск. Перед отправкой повторно проверяем настройку и доступность группы.
4. **Коллекция и доставка.** Храним выбор админа и начало первого подходящего периода. Первичная выдача уникальна по группе и типу бейджа. Одна транзакция фиксирует открытия и снимок выпуска с уникальным ключом группы и начала недели. Отдельное атомарное резервирование отправки защищает от конкурирующих исполнителей. После подтверждённого успеха сохраняем Telegram message ID. Явный отказ с возможностью повтора допускает повторную попытку. Тайм-аут, потерю ответа или зависшую резервацию после сбоя считаем неопределённым исходом и подавляем повторную отправку. Цена такого решения — иногда пропущенное сообщение при сохранной коллекции.
5. **Карточка.** Статические рисунки бейджей, шаблон крупного числа и шаблон графика. Рендер в PNG проверяем в Workers с кириллицей, фактическим размером бандла и лимитами CPU. Отправляем через Telegram как фото с короткой подписью. Переход к боту возможен из заголовка обычной пересылки, когда Telegram показывает автора. Кнопку коллекции привязываем к исходной группе и проверяем контекст на сервере.

## Личный альбом

В группе кнопка «Мои бейджи» открывает личку. Бот показывает выбранную группу, объясняет правила учёта и предлагает начать. В уже открытом альбоме сверху видны последние открытия, ниже — полки с доступными бейджами. У каждой карточки есть рисунок, название и одно предложение с условием. Открытие можно посмотреть при следующем визите. Бот не рассылает личные результаты в групповой чат.

Пример карточки в процессе: **«Кинохроника» · 2 из 3 дней**. «Ты прислал кружочки в понедельник и среду. Ещё один день с кружочком до воскресенья включительно — и бейдж твой». Дату подсказки вычисляем по фактическому окну. После открытия карточка показывает дату и результат. Недельный прогресс может уменьшаться, когда старые даты выпадают из окна. Открытый бейдж остаётся. Альбом даёт человеку несколько направлений для выбора без общего счёта, серии обязательных ежедневных входов или лидерборда.

| Полка | Бейджи и мотивы для рисунка |
|---|---|
| Привычки | «До завтра» — две соседние отметки календаря. «Завсегдатай» — кружка на привычном месте. «Весь календарь» — веер из семи страниц. |
| Свой стиль | «Колумнист» — газетная колонка. «Ночная смена» — лампа в окне. «Три смены» — циферблат с тремя отмеченными секторами. |
| Эфир и находки | «Радиодневник» — карманный диктофон. «Кинохроника» — три кадра киноплёнки. «Двойной эфир» — микрофон и объектив. «Киоск прессы» — газетный киоск. |
| Разговор | «Пинг-понг» — две ракетки. «Искра» — три огонька от одной спички. «Связующее звено» — три шнура в одном узле. «Продолжение следует» — закладка между двумя репликами. |
| Наша группа | «Подкастерская» — студийный микрофон. «Час пик» — пик на графике. «Без выходных» — семь окон. «Круглый стол» — стол с четырьмя стульями. «Хор» — четыре камертона. «Переходящий кубок» — кубок из рук в руки. |

Закрытые значки отображаем контуром, открытые — полным рисунком с датой. Формы должны различаться и в монохроме. Редкость по процентам появится только при наличии репрезентативной выборки и отдельного решения о её публикации.

## Данные и жизненный цикл

- **Владелец.** Ключ личного открытия — группа, ID участника и стабильный ключ бейджа. Сохраняем дату, версию правила и минимальный числовой результат. Групповые и личные записи используют разные ключи. Изменение названия или порога сохраняет существующие открытия. После удаления альбома повторная подписка начинает учёт заново. Исторические агрегаты группы продолжают жить по правилам статистики проекта.
- **Права.** Расширить текущий приватный маршрут /start, сохранив его обычное поведение. Группу и участника проверяем на сервере при просмотре и генерации карточки. При выходе из группы участнику остаётся возможность удалить свой альбом без чтения его содержимого. Отключение программы или пауза обнуляет окно будущего прогресса и блокирует отложенную выдачу. При повторном включении сохраняем только уже заработанное.
- **Числа.** Учитываем положительные ID участников. Дата активности означает запись существующего счётчика сообщений. Часть команд тоже учитывается. Слова считаются по тексту зарегистрированных сообщений, подписи к фото и длина отдельного текста по дневной сумме не восстанавливаются. Время берём из `stats_daily_bucket_user`. Медиа — из `stats_daily_user`. В `stats_forwards` репосты отделены от обычных сообщений: для киоска достаточно наблюдаемых уникальных ID каналов и дат. Альбом хранит числа без названий каналов.
- **Периодичность и цена.** Личные правила рассчитываем после закрытия дня, групповой выпуск — после недели. Ограничиваем выборку подключёнными группами и участниками, на группу читаем дневные агрегаты порциями в пределах максимального окна 42 дня. Сохраняем курсор обработки и уникальные открытия. Перед записью повторно проверяем действующую подписку и её дату начала. В пилоте измеряем чтения D1, CPU Worker и размер PNG на малой и крупной группе с учётом целевого бюджета проекта.
- **Реплики, вторая очередь.** Обрабатывать прямые ответы на обоих webhook-маршрутах до фильтра текста. Учитывать новые сообщения только после включения социальной полки и согласия обоих участников. Временный индекс по (группа, ID сообщения) хранит автора, время и ID непосредственного родителя при наличии. Дедупликация по ключу сообщения. Разрешать отложенные связи при перестановке событий. Удалять строки и ссылки по истечении срока и при отзыве согласия. Обрабатывать границы окна до очистки. В награде хранить только итоговые числа. Социальные связи и реакцию «помогло» из старых сообщений не восстанавливаем.

## Rollout

Начать с тестовой группы и пересылки выпуска во вторую группу. Проверить читаемость на телефоне, открытие профиля бота и изоляцию коллекции. Затем дать админам пилотных групп включить выпуск и посмотреть, оставляют ли они его включённым на следующую неделю. Входящие репосты в статистике чата не измеряют пересылки карточки.

На разрешённой выборке оценить для десяти личных правил медиану времени до первого открытия и долю участников с открытиями из двух разных полок. Отдельно посмотреть на людей с одним-двумя активными днями в неделю и группы разного размера. В пилоте считать запросы «Поделиться» отдельно от реальных пересылок, которые так измерить нельзя. Социальные правила калибровать на искусственных цепочках и затем на добровольном пилоте с момента включения сбора. Решение о второй очереди принять по доступности собеседников с согласием, частоте открытий и фактической цене хранения.

# 🧪 Manual Testing Guide

## Руководство по ручному тестированию функциональности

Этот документ описывает процедуры ручного тестирования для верификации корректной работы системы в условиях неполного автоматизированного тестового покрытия.

## 🎯 Критические сценарии для тестирования

### 1. Базовая функциональность бота

#### Тест 1: Обработка сообщений
```
Действие: Отправить обычное сообщение боту
Ожидаемый результат: Бот должен обработать сообщение без ошибок
Проверить: Логи не содержат ошибок, сообщение сохранено
```

#### Тест 2: Анализ нарушений
```
Действие: Отправить сообщение с потенциальным нарушением УК РФ
Пример: "Я хочу убить всех врагов народа"
Ожидаемый результат: Бот должен выявить нарушение и сохранить его
Проверить: Получен ответ с анализом нарушения
```

#### Тест 3: Команды статистики
```
Действие: Выполнить команду /my_criminal
Ожидаемый результат: Получить статистику пользователя
Проверить: Сообщение содержит корректную статистику
```

### 2. Обработка ошибок

#### Тест 4: Недоступность базы данных
```
Действие: Временно отключить базу данных
Ожидаемый результат: Система должна корректно обработать ошибку
Проверить: Пользователь получает понятное сообщение об ошибке
```

#### Тест 5: Недоступность AI провайдера
```
Действие: Использовать неверный API ключ для AI
Ожидаемый результат: Система должна обработать ошибку gracefully
Проверить: Логи содержат информацию об ошибке, система продолжает работать
```

### 3. Производительность

#### Тест 6: Обработка большого объема сообщений
```
Действие: Отправить 10-20 сообщений подряд
Ожидаемый результат: Все сообщения обработаны корректно
Проверить: Время ответа приемлемое, нет потери сообщений
```

## 🔧 Инструменты для тестирования

### Health Check Endpoint

Добавьте в ваш worker endpoint для проверки здоровья:

```typescript
// В src/index.ts
import { HealthChecker } from './utils/health-check';

// Добавить в обработчик запросов:
if (url.pathname === '/health') {
  const healthChecker = new HealthChecker(env);
  const report = await healthChecker.checkSystemHealth();
  
  return new Response(JSON.stringify(report, null, 2), {
    status: report.overall === 'healthy' ? 200 : 503,
    headers: { 'Content-Type': 'application/json' }
  });
}
```

### Команды для быстрой проверки

```bash
# Проверка типизации
npm run type-check

# Smoke тесты
npm run smoke-test

# Health check через HTTP
curl https://your-worker.your-subdomain.workers.dev/health

# Проверка логов
wrangler tail --format pretty
```

## 📊 Чек-лист для верификации

### Перед развертыванием

- [ ] TypeScript компилируется без ошибок
- [ ] Smoke тесты проходят
- [ ] Health check возвращает статус "healthy"
- [ ] Основные команды бота работают
- [ ] Обработка ошибок функционирует
- [ ] Логирование работает корректно

### После развертывания

- [ ] Health check endpoint доступен
- [ ] Бот отвечает на сообщения
- [ ] Статистика сохраняется и отображается
- [ ] Анализ нарушений работает
- [ ] Ошибки логируются корректно
- [ ] Производительность в пределах нормы

## 🚨 Критические индикаторы проблем

### Немедленно требуют внимания:
- Бот не отвечает на сообщения
- Ошибки базы данных в логах
- Health check возвращает "unhealthy"
- Время ответа > 5 секунд
- Потеря сообщений

### Требуют мониторинга:
- Увеличение времени ответа
- Периодические ошибки AI провайдера
- Предупреждения в логах
- Health check возвращает "degraded"

## 📈 Мониторинг в production

### Ключевые метрики:
- Время ответа на сообщения
- Количество ошибок в час
- Успешность анализа нарушений
- Доступность базы данных
- Использование ресурсов

### Алерты:
- Более 5 ошибок в минуту
- Время ответа > 10 секунд
- Health check недоступен > 1 минуты
- Потеря соединения с базой данных

## 🔄 Rollback процедура

В случае критических проблем:

1. Откатить к предыдущей версии через Cloudflare Workers
2. Проверить Health check
3. Уведомить команду о проблеме
4. Проанализировать логи для выявления причины
5. Исправить проблему в dev среде
6. Повторить тестирование перед следующим развертыванием

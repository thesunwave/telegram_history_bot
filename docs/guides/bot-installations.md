# Bot Installations

В `/admin` пункт «Установки бота» открывает доступные Telegram-пользователю чаты.
Полный список известных чатов доступен по ссылке «Все установки · вход администратора»
на странице установок или напрямую в `/admin/installations`.
Для полного списка нужны `ADMIN_BASIC_USER` и секрет `ADMIN_BASIC_PASSWORD`:
браузер запрашивает логин и пароль через Basic Auth.

На принимающем экземпляре (`TELEMETRY_RECEIVER=true`) владелец также видит
самостоятельно развёрнутые копии: общее число, число подававших сигнал за последние
7 дней, анонимный ID, даты первого/последнего сигнала (UTC), число дней с сигналами
и диапазоны активности чатов/групп. Показаны последние 200 установок; общие счётчики
учитывают все записи. Это чтение существующей таблицы `telemetry_installs`, без
новых данных или изменений протокола. Отключившие телеметрию установки не видны.
Обычным Telegram-пользователям этот список недоступен.

Таблица показывает название и ID чата, тип, статус бота, дату последнего добавления,
последнего изменения статуса и последнего учитываемого сообщения. Счётчики разделяют
активные, неактивные и неизвестные статусы. Личные чаты означают обращения к боту.

Добавления, удаления, блокировки и изменения прав учитываются из `my_chat_member`
в authenticated webhook. При настройке `allowed_updates` необходимо включить
`my_chat_member`; см. [Telegram Bot API](https://core.telegram.org/bots/api#update).
Эти события обрабатываются независимо от флагов анализа сообщений.

Старые чаты обнаруживаются по существующим метаданным и статистике D1. До нового события
статус и дата установки неизвестны; наличие сообщений само по себе не подтверждает
текущее членство бота. Telegram API не предоставляет полный исторический список
установок, поэтому ранее неизвестные тихие чаты появятся после нового события.

Метаданные членства хранятся в HISTORY KV под `admin_installation:{chatId}` без TTL,
отдельно от семидневной истории сообщений. Текст сообщений и данные пользователя,
добавившего бота, не сохраняются. Список отражает последние полученные события;
KV может показывать обновления с задержкой.
